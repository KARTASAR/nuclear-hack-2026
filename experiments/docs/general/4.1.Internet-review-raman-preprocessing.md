# Обзор практик из статей: preprocessing Raman-данных для ML

Документ фиксирует, что удалось найти в публикациях, и какие выводы из этого применимы к нашим данным в `data/real`.

## 1) Что именно искали

Фокус поиска:

- как обычно чистят Raman-спектры перед классификацией;
- какие baseline-методы считаются рабочими;
- как делают нормализацию/коррекцию рассеяния;
- как обрабатывают сдвиги по волновому числу;
- как валидируют модели, чтобы не ловить leakage.

## 2) Что выглядит «устоявшейся практикой» по литературе

### 2.1 Базовый порядок preprocessing

В литературе и обзорах повторяется общий каркас:

1. удаление спайков/cosmic rays;  
2. сглаживание (часто Savitzky–Golay);  
3. коррекция baseline (флуоресценция);  
4. нормализация/коррекция рассеяния (SNV/MSC/EMSC и т.п.);  
5. опционально производные признаки и/или feature extraction.

Опора:

- обзор по preprocessing спектральных данных (iScience 2025);
- классические работы по SG, SNV/MSC/EMSC;
- прикладные Raman-статьи по биомедицине.

### 2.2 Baseline correction: penalized least squares — «рабочий стандарт»

Семейство AsLS/airPLS/arPLS постоянно встречается как практический baseline по качеству/скорости.

- `airPLS` (Analyst, 2010): автоматическая итеративная подстройка весов без явного peak picking.
- `arPLS` (Analyst, 2015): улучшение airPLS, более устойчивое на шуме, более стабильная оценка baseline.

Отдельно есть сильные альтернативы:

- морфологические adaptive-алгоритмы (Appl Spectrosc, 2019);
- SERDS (инструментальный подход), в сравнении с computational correction (Sensors, 2017).

### 2.3 Нормализация и scatter correction

Для vibrational spectroscopy стабильно упоминаются:

- `SNV` (классика);
- `MSC` (классика);
- `EMSC` (расширенная модельная коррекция).

Ключевая практическая мысль: нет «одной лучшей» нормализации на все наборы, метод подбирается под физику и задачу (обзоры 2009/2013, tutorial по EMSC 2012).

### 2.4 Межприборная переносимость и drift

Для Raman это отдельная проблема:

- EMSC использовали как preprocessing для model transfer между приборами (Analytical Chemistry, 2018), улучшая внешнюю валидацию по устройствам;
- есть работы по коррекции peak shifts до PLS (Chemometrics and Intelligent Laboratory Systems, 2000);
- есть современные протоколы калибровки волнового числа (Appl Spectrosc, 2024).

### 2.5 Валидация: делать split по пациенту/животному, а не по спектрам вперемешку

В медицинских Raman-работах регулярно используют `leave-one-patient-out`/`leave-one-lesion-out`.

Важный сигнал из литературы: «наивный» split по спектрам (когда спектры одного пациента попадают и в train, и в test) завышает качество; это прямо отмечено в ряде работ как риск overfitting/leakage.

## 3) Что это значит для нашего датасета (выводы на основе источников)

Ниже — **инференс** (применение найденных практик к нашим данным), а не цитата статей.

1. Для старта стоит держаться классического пайплайна `despike -> smoothing -> baseline -> normalization`.
2. В baseline-кандидаты первой очереди: `airPLS` и `arPLS` (плюс одна альтернатива — морфологический adaptive).
3. Для нормализации сравнить минимум `SNV`, `MSC`, `EMSC` (а не фиксировать один метод заранее).
4. Обязательно делать групповой split по животному (`mouse`), иначе вероятен leakage.
5. Из-за двух окон (`center1500`/`center2900`) желательно сначала раздельные модели и только потом объединение.
6. Из-за плавающей wave-сетки между файлами нужен шаг harmonization (интерполяция/ре-сэмплинг на общую сетку) + контроль сдвигов.

## 4) Насколько полезен поиск для нас

Поиск дал практическую пользу:

- нашёлся стабильный «костяк» preprocessing-пайплайна;
- нашлись конкретные baseline-алгоритмы, которые стоит сравнивать первыми;
- подтверждена критичность group-wise валидации;
- есть отдельные практики для приборного drift/сдвигов.

То есть сейчас нет необходимости «действовать полностью вслепую»: у нас есть обоснованный стартовый набор решений.
