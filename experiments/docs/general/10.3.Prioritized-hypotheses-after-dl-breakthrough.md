# Prioritized Hypotheses After DL Breakthrough

Дата: `2026-03-06`  
Контекст: текущий зафиксированный reference-кандидат (после locked-check) — `P2 ensemble: 1500_top3 + 2900_top4 + alpha_1500=0.07`.

## 1) Правило приоритизации

Приоритет = ожидаемый прирост `macro_f1` x вероятность успеха / время и риск нестабильности.

## 2) Очередь гипотез (от самого перспективного к менее перспективному)

| Priority | Гипотеза | Ожидаемый потенциал | Вероятность успеха | Сложность |
|---|---|---:|---:|---:|
| P1 | Fusion 2.1: fine alpha + per-class weights + calibration | +0.01..0.03 | Высокая | Низкая |
| P2 | Seed-ensemble внутри окна + fusion | +0.005..0.02 | Высокая | Низкая |
| P3 | Узкий HPO для `ramannet1500` | +0.005..0.02 | Средне-высокая | Средняя |

## 3) Детализация по шагам

### P1. Fusion 2.1

Проверяем:

1. `alpha` с шагом `0.01` вместо `0.05`;
2. per-class fusion weights;
3. калибровка вероятностей перед fusion (temperature / Platt).

Критерий успеха:

1. `macro_f1_mean` выше текущего best минимум на `+0.007`;
2. `balanced_accuracy_mean` не падает.

### P2. Seed-ensemble в окнах

Проверяем:

1. усреднение `proba` топ-2/топ-3 seed для `1500` и `2900`;
2. поверх этого — повторный fusion sweep.

Критерий успеха:

1. снижение `std` по seed;
2. стабильный прирост mean-метрик.

### P3. HPO `ramannet1500`

Проверяем:

1. `torch_lr`: `0.0005/0.001/0.0015`;
2. `ramannet_dropout`: `0.1/0.2/0.3`;
3. `ramannet_segments`: `48/64/80`;
4. `torch_weight_decay`: `1e-4/3e-4/1e-3`.

Критерий успеха:

1. лучший конфиг проходит stability-check на `split_seed=11/22/33`.

### P4. HPO `spectral_transformer2900`

Проверяем:

1. `transformer_patch_size`: `8/16/32`;
2. `transformer_num_layers`: `2/3/4`;
3. `transformer_dropout`: `0.1/0.2/0.3`;
4. `torch_lr`: `5e-4/8e-4/1e-3`.

Критерий успеха:

1. прирост по `macro_f1_mean` без роста дисперсии.

### P5. Spectral augmentation

Проверяем:

1. small Gaussian noise;
2. intensity scaling;
3. minor x-axis shift/jitter в безопасных пределах.

Критерий успеха:

1. рост quality на seed-стабильности, не только single-run.

### P6. Loss/regularization tuning

Проверяем:

1. class-weighted CE;
2. label smoothing;
3. focal loss (как опциональный).

Критерий успеха:

1. улучшение `macro_f1` без деградации minority-class recall.

### P7. Single-step preprocessing CNN

Проверяем:

1. вариант end-to-end, где часть preprocessing учится моделью;
2. сравнение с текущим DL winner в идентичном CV-протоколе.

Критерий успеха:

1. минимум сопоставимое качество при приемлемой стабильности.

### P8. Map-aware MIL

Проверяем:

1. bag=`map points`, attention pooling;
2. сравнение с `file_mean` pipeline.

Критерий успеха:

1. прирост качества или заметный плюс по интерпретируемости без потери стабильности.

### P9. Новые архитектуры

Проверяем:

1. только если P1-P6 исчерпаны и есть бюджет времени.

Критерий успеха:

1. >`+0.01` к текущему stable best, иначе no-go.

## 4) Stop-rules (обязательные)

1. Если гипотеза после quickscreen не даёт сигнала, не тратим время на глубокий прогон.
2. Если improvement < шума между split-seed, гипотеза отклоняется.
3. Каждую прошедшую гипотезу закрепляем через `mean/std` на нескольких split.

## 8) Locked-Holdout Check for P2 (selection bias control)

Дата: `2026-03-06`.

Протокол:

1. фиксированный holdout-группы по `mouse`: `mk1`, `mend1`, `mexo1` (по одному `mouse` на класс);
2. обучение и CV только на остальных группах (`cv_samples=100`, `holdout_samples=18`);
3. ранжирование run’ов и выбор `(top-k, alpha)` только по `split=cv`;
4. финальная оценка выбранной комбинации только на `split=holdout` (без ретюна по holdout).

Что запускали:

1. `1500`: `p2lk_1500_ramannet_ss11/22/33/42`;
2. `2900`: `p2lk_2900_trpatch8_ss11/22/33/42`.

Результат (выбор по CV):

1. selected: `1500_top3 + 2900_top4`, `alpha_1500=0.07`;
2. `cv_macro_f1=0.7888`;
3. `holdout_macro_f1=0.6481`, `holdout_bal_acc=0.6667`.

Сравнение с fallback (`top1 + top1`, также selection на CV):

1. fallback holdout: `macro_f1=0.5278`, `bal_acc=0.5556`;
2. selected-by-cv лучше на holdout на ~`+0.120` macro-F1.

Вывод после locked-check:

1. `P2` теперь не просто “под вопросом”: есть независимый сигнал на holdout;
2. принимаем `P2` как **Go (validated with locked protocol)**;
3. фиксируем его как текущий основной baseline для последующих сравнений;
4. при этом держим caution: holdout маленький (`n=18`), поэтому сохраняем fallback-кандидат.
