# Реальные данные (`data/real`) — как устроены и как с ними работать

Этот файл фиксирует текущее состояние реальных данных в репозитории и служит как onboarding-справка для новых участников.

## 1. Где лежат данные

Корневая папка:

`data/real/`

Внутри 3 класса:

- `data/real/control`
- `data/real/endo`
- `data/real/exo`

В каждом классе есть подпапки по животным (например: `mk1`, `mk2a`, `mend2b`, `mexo3`), а внутри — `.txt` файлы карт.

## 2. Что физически хранится в одном `.txt` файле

Основной формат (почти все файлы):

- Заголовок: `#X  #Y  #Wave  #Intensity`
- Далее строки измерений.

Это **не один спектр**, а **карта спектров**:

- `#X`, `#Y` — координата точки на карте.
- `#Wave` — волновое число (Raman shift, см⁻¹).
- `#Intensity` — интенсивность.

По факту один файл = набор точек карты, и в каждой точке есть спектр по оси `Wave`.

## 3. Сводка по текущему набору

По состоянию текущих файлов в `data/real`:

- Всего `.txt` файлов: `239`
- По классам:
  - `control`: `80`
  - `endo`: `75`
  - `exo`: `84`
- Почти все файлы 4-колоночные (`#X #Y #Wave #Intensity`): `237`
- Специальные 2-колоночные `Average`-файлы (`#Wave #Intensity`): `2`

Типичные размеры 4-колоночного файла:

- `n_rows = 532875`
- `n_points = 525` (точек карты)
- `n_waves = 1015` (значений по оси wave)

Проверка: `532875 = 525 * 1015`.

## 4. Два спектральных окна (center1500 / center2900)

В именах файлов есть токен:

- `center1500`
- `center2900`

Это два разных диапазона wave:

- `center1500`: примерно `~926 ... ~2002` см⁻¹
- `center2900`: примерно `~2459 ... ~3288` см⁻¹

Важно:

- Это **не один непрерывный диапазон**.
- Между окнами есть разрыв (`~2002...2459`).
- Текущий код в репозитории был настроен на диапазон `600...1800` и бинарную задачу, поэтому «как есть» к новым данным он не подходит.

## 5. Именование файлов: что можно извлечь

Пример:

`cortex_left_endo_2Agroup_633nm_center1500_obj100_power100_1s_5acc_map35x15_step2_place2_1.txt`

Из имени обычно можно извлечь:

- область мозга: `cortex`, `striatum`, `cerebellum`
- сторону: `left/right` (если есть)
- класс: `control/endo/exo`
- группу в протоколе: `1group`, `2Agroup`, `2Bgroup`, `3group`
- окно: `center1500/center2900`
- место измерения: `place...`
- повтор: последний суффикс `_1`, `_2`, `_3`, `_4` (зависит от файла)

## 6. Обнаруженные аномалии (важно)

1. Два файла `*_Average.txt` имеют формат `#Wave #Intensity` (2 колонки), это уже усреднённые спектры:

- `data/real/endo/mend2a/cortex_left_endo_2Agroup_..._center2900_..._place1_1_Average.txt`
- `data/real/endo/mend2a/striatum_left_endo_2Agroup_..._center1500_..._place1_3_Average.txt`

2. Один файл с неконсистентным именем/содержимым:

- `data/real/endo/mend1/cortex_endo_1group_..._center2900_..._place2.txt`

Хотя в имени `center2900`, его wave-диапазон фактически соответствует `center1500`.

3. Сетка wave слегка «плавает» между файлами (мин/макс немного отличаются), поэтому для объединения файлов лучше делать интерполяцию на общую референс-сетку.

## 7. Что считать «одним sample» (ключевое решение)

Есть как минимум 3 уровня:

1. **Точка карты**: одна координата `(X, Y)` = один спектр.
2. **Файл-карта**: агрегация всех точек файла (например, mean/median спектр).
3. **Животное/область**: агрегация нескольких карт.

От выбора уровня зависит:

- размер датасета,
- риск ликиджа,
- сложность модели.

## 8. Рекомендованный базовый протокол работы с данными

1. Жёстко фильтровать проблемные файлы:
- исключить `*_Average.txt` из основного обучения;
- отдельно решить судьбу «аномального» `center2900` файла из `mend1`.

2. Разделить эксперименты по окнам:
- сначала `center1500` отдельно,
- затем `center2900` отдельно,
- только потом пробовать объединение.

3. Привести все спектры к общей сетке wave (интерполяция).

4. Делать split по группе животного (`mouse`), а не случайно по точкам, иначе будет утечка.

5. Метрики считать для **3-классовой** задачи (`control`, `endo`, `exo`):
- macro-F1,
- balanced accuracy,
- confusion matrix,
- при необходимости multiclass ROC-AUC (OvR).

## 9. Почему текущий код не является «истиной» для этих данных

Текущий код в репозитории изначально ориентирован на тестовый/фейковый сценарий:

- вход как CSV в tabular/wide формате;
- бинарные метки;
- окно предобработки `600..1800`.

Реальные данные:

- в формате map `.txt`,
- с 3 классами,
- и с двумя окнами (`1500/2900`).

Итог: текущую архитектуру можно использовать как основу, но нужна адаптация пайплайна загрузки/предобработки/валидации под реальный формат.

## 10. Мини-чеклист для нового участника

Перед запуском любой модели проверь:

1. Какие файлы включены/исключены (`Average`, аномалии).
2. Как выбран уровень sample (точка/карта/животное).
3. Как построена общая сетка wave.
4. Что split идёт по `mouse` (или эквивалентной группе).
5. Что задача реально multiclass (3 класса), а не бинарная.
